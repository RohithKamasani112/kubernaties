1. 📝 To-Do List App
User Story:
“As a user, I want to add a task and have it stay on the screen even after refreshing.”

Defect:
Tasks disappear after refresh.

Included Files:

index.html, style.css, app.js

Bug Source:
localStorage.setItem() missing or getItem() not called on load.

Learner Goal:
Fix task saving and loading logic.

Hint for LLM:

Check for missing localStorage.setItem() and JSON.parse() on load.

2. 🔐 Login Page with Validation
User Story:
“As a user, I want to get an error if I submit an empty form.”

Defect:
Empty fields are being submitted.

Files:

login.html, login.js, style.css

Bug Source:
preventDefault() missing, or no input validation logic.

Goal:
Add proper validation logic.

Hint for LLM:

Create a function to validate email/password fields, and display error messages.

3. 💬 Comment Box (Basic Forum Post)
User Story:
“When I type a comment and click submit, it should appear below.”

Defect:
Nothing is displayed after clicking "Submit".

Files:

index.html, comments.js

Bug:
DOM not updated or value not read from textarea.

Hint:

Check if .value is being accessed, and DOM node is correctly appended.

4. 🎨 Dark Mode Toggle
User Story:
“As a user, I want to toggle between light and dark mode.”

Defect:
Button exists but doesn’t change anything.

Files:

index.html, style.css, darkmode.js

Bug:
classList.toggle() missing or incorrect class name.

Hint:

Toggle a .dark class on the <body> or wrapper div.

5. ⏲️ Countdown Timer
User Story:
“I want to set a timer and see it count down.”

Defect:
Timer sets but doesn’t count down.

Files:

index.html, timer.js

Bug:
setInterval() logic broken or missing clearInterval().

Hint:

Fix countdown logic inside setInterval() loop.

6. 📧 Newsletter Form (with Regex Email Check)
User Story:
“When I enter an invalid email, I should see an error.”

Defect:
Form submits even with junk input.

Files:

form.html, style.css, validate.js

Bug:
Email not validated using regex.

Hint:

Use /^[^\s@]+@[^\s@]+\.[^\s@]+$/ to validate email.

7. 🛒 Shopping Cart Quantity Bug
User Story:
“When I click + or −, item quantity should update and total price recalculate.”

Defect:
Quantity updates but total price stays wrong.

Files:

cart.html, cart.js

Bug:
Total not recalculated after quantity change.

Hint:

Recalculate total = quantity * price in the click event handler.

8. 🔍 Search Filter for List Items
User Story:
“As I type, I want the list to show only matching items.”

Defect:
Typing does nothing.

Files:

index.html, search.js, style.css

Bug:
keyup event or .includes() logic missing.

Hint:

Loop through list items and hide non-matching ones with .style.display = 'none'.

9. 🎥 Movie Cards Grid (Image & Text from JSON)
User Story:
“When the page loads, it should show a grid of movie posters and titles.”

Defect:
No movies display.

Files:

index.html, movies.js, data.json

Bug:
JSON not fetched or parsed, or HTML not generated.

Hint:

Use fetch('data.json') and createElement() to build the grid.

10. 📆 Calendar Date Picker
User Story:
“When I click a date, it should highlight and show below.”

Defect:
Clicking date doesn’t update anything.

Files:

calendar.html, calendar.js, style.css

Bug:
addEventListener missing on dates or wrong ID used.

Hint:

Attach click event to .date elements and update selected date div.

✅ How to Structure for the LLM
When passing to the LLM, use this prompt format for each project:

plaintext

Edit
You are helping me create a fix-the-bug coding lesson.

Project Name: ToDo App with LocalStorage

User Story: "As a user, I want my tasks to persist after refreshing."

Problem: Tasks disappear after refreshing.

Files:
- index.html: Contains input, button, and task list
- app.js: Handles task logic

Bug:
- localStorage not used or loaded properly

What the student must do:
- Save tasks to localStorage
- Load them on page load
- Display them in the DOM

Give:
- Starting boilerplate code with the bug in place
- Hint section
- Solution section (optional toggle)
- Test logic to check if localStorage is being used

✅ 1. Project Selection Panel (Bug-Based Learning)
What it is:
A list of mini-projects with bugs or missing features.

Why it matters:
Lets learners pick realistic, hands-on tasks like:

"Fix the dark mode toggle"

"Add validation to login form"

"Make tasks persist in localStorage"

Must have:

Title

Brief story (“User can't save task”)

Difficulty tag (Beginner / Intermediate)

Files involved (index.html, style.css, app.js)

✅ 2. Code Editor (Monaco or Web-based)
What it is:
A full code editing experience with syntax highlighting.

Why it matters:
This is where learners fix bugs, write code, and experiment.

Must have:

Multi-tab editor (HTML / CSS / JS)

Autocomplete + line numbers

Optional AI hint button

Save & Run

✅ 3. Live Preview (Right Panel)
What it is:
Real-time preview of the HTML/CSS/JS output.

Why it matters:
Visual feedback is key to frontend learning. Learners can see their fixes live.

Must have:

Refresh on Save or Run

Mobile/Desktop preview toggle (bonus)

Console tab to show errors

✅ 4. AI Tutor / Debug Helper (Sidebar or Chatbot)
What it is:
A chat-like assistant powered by an LLM to guide learning.

Why it matters:
Gives help without spoiling the answer, enabling deeper learning.

What it should do:

Explain the bug in plain English

Ask guiding questions (not just give solutions)

Offer hints or analogies

Suggest best practices after solving

✅ 5. Instructions + User Story Panel
What it is:
Describes what the user is supposed to fix or build.

Why it matters:
Puts the learner in the shoes of a real developer solving a user problem.

Include:

“The login page submits blank data — fix the validation”

Acceptance criteria

Bonus task (like “Show an error below the input”)

✅ 6. Terminal / Logs / Console
What it is:
A panel showing console logs and runtime errors.

Why it matters:
Helps learners debug like real developers by reading logs.

✅ 7. Predefined Tests (Hidden or Shown)
What it is:
Small auto-tests that verify the bug is fixed.

Why it matters:
Gives instant feedback — “Yes, your fix works!”

Optional:

Use assert or a lightweight test runner

Show test result as pass/fail (like: ✅ Task saves correctly)

✅ 8. Hint / Solution Toggle
What it is:
Let the user reveal 1–2 hints, then optionally the solution.

Why it matters:
Supports learning without frustration.

✅ 9. Progress Tracking + Scoring
What it is:
Track how many bugs/projects a learner has completed.

Why it matters:
Gamifies learning and motivates continuation.

Ideas:

“5 projects completed”

“Fixed 3 bugs with no hints”

Leaderboard for classroom/cohort settings

✅ 10. Custom Prompt Mode (For Educators or Advanced Users)
What it is:
Let a teacher or user ask the LLM:

"Inject a bug into this login form"

"Generate a project that teaches closures"

"Create a bug-fixing challenge for dark mode"

Why it matters:
Allows unlimited auto-generated learning tasks from simple prompts.
